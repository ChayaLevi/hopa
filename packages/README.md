# packages — the client engine

Four Kotlin modules that the Android app and the Windows sidecar both build. No
`main`, no UI, no Android SDK.

| module | holds | package | depends on |
|---|---|---|---|
| `engine` | loop, gate, prompt, observation, records, router, parser, contracts, ports | `com.hopa.engine.*` | `knowledge` |
| `knowledge` | generated catalog, approval policy data, prompt rules | `com.hopa.knowledge.*` | nothing |
| `stores` | conversation, settings, approval, memory and skill stores, plus their models | `com.hopa.stores.*` | `engine` |
| `net` | the OpenAI-compatible model client, the stub, and the PC bridge client | `com.hopa.net.*` | `engine` |

```
apps/android ─┐
              ├─> engine ──> knowledge
apps/windows ─┘      ↑
                     ├── stores
                     └── net ──> okhttp
```

## Rules

1. **`engine` imports no Android, no HTTP.** `checkNoAndroidImports` in Gradle
   and `tools/checks/check-android-structure.py` fail the build on a violation.
2. **`knowledge` is generated.** Every file starts with `// Generated by`; edit
   the source under `contracts/` or `services/brain/knowledge`, then regenerate.
3. **`stores` holds contracts, not storage.** Room, DataStore and Keystore live
   in `apps/android/data`; the interfaces they implement live here.
4. **`net` is the only module that speaks HTTP.** `engine` defines `ModelPort`;
   `net` implements it. A device reached over the bridge (`AdbDevice`) is a port
   in `net`, next to the client that reaches it, because the Windows sidecar uses
   it too.
5. **A local model is not `net`.** An on-device runtime is a separate adapter
   behind the same `ModelPort`; it never travels through `net`.
6. **One name, one module.** `com.hopa.engine`, `com.hopa.knowledge`,
   `com.hopa.stores` and `com.hopa.net` belong to these four modules.
   `com.hopa.capabilities` and `com.hopa.data` belong to the platform adapters in
   `apps/android`.
7. **No client imports another client.** Both import `packages/`.
8. **Generated files are committed**, and `--check` fails when they drift.

## What a client supplies

```
TurnContext(goal, history, memory, skills, installedApps, appFunctions,
            platform, vision, phoneAccess)
        |
        v
   AgentLoop  ->  TurnResult(records, answer, options, narration, usage, error)
```

The client also provides the ports: a `DevicePort` (accessibility, hidden display
or bridge), an `ApprovalGateway` (the sheet), a `RunRecorder` (Room or memory), a
`Clock`, and a `ModelPort` — from `net` today, from a local runtime later.

## Build and test

```
./gradlew :engine:test :knowledge:compileKotlin :stores:test :net:test
./gradlew :app:compileDebugKotlin
./gradlew -p ../windows/sidecar test
```

## Generated code

| output | source | command |
|---|---|---|
| `knowledge/.../catalog/AppCatalog.kt` | `services/brain/knowledge/apps/*/APP.md`, `.../sites/*` | `build-app-catalog.py --kotlin` |
| `knowledge/.../policy/ApprovalPolicyData.kt` | `contracts/policy/approval.v1.json` | `build-policy-data.py --kotlin` |
| `knowledge/.../prompt/PromptRules.kt` | `contracts/prompts/rules.v1.json` | `build-prompt-rules.py --kotlin` |

Each script also writes the ArkTS copy under `apps/harmony`. Add `--check` to any
of them to verify the committed files instead of writing.
