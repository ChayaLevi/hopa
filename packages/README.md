# packages — the client engine

Six Kotlin modules that the Android app and the Windows sidecar both build. No
`main`, no UI, no Android SDK.

| module | holds | package | depends on |
|---|---|---|---|
| `contracts` | wire types, port interfaces, model types, approval data classes, JSON helpers | `com.hopa.contracts.*` | nothing |
| `engine` | loop, gate, prompt, observation, records, router, parser | `com.hopa.engine.*` | `contracts`, `knowledge` |
| `turn` | one turn for every client: goal, checkpoints, recipes, plan gate, playbooks | `com.hopa.turn.*` | `contracts`, `engine` |
| `knowledge` | generated catalog, approval policy data, prompt rules | `com.hopa.knowledge.*` | nothing |
| `models` | the adapters behind `ModelPort`: provider choice and state, the OpenAI-compatible client, the stub | `com.hopa.providers.*` | `contracts` |
| `net` | device and backend transport: the PC bridge client and the gateway client | `com.hopa.transport.*` | `contracts` |

```
apps/android ─┐
              ├─> turn ──> engine ──> knowledge
apps/windows ─┘      │        └──> contracts
                     ├── models ──> contracts ──> okhttp
                     └── net ─────> contracts ──> okhttp
```

## Rules

1. **`contracts` is the leaf.** It holds the types every other module passes
   around and depends on nothing of ours. No loop, no logic, no HTTP.
2. **`turn` is the only place a goal becomes steps.** Recipes, the plan gate,
   checkpoints and a playbook policy live here, so the chat, a parallel run and a
   delivered task all take the same path. A client supplies ports, not policy.
3. **`engine` imports no Android, no HTTP.** `checkNoAndroidImports` in Gradle
   and `tools/checks/check-android-structure.py` fail the build on a violation.
4. **`knowledge` is generated.** Every file starts with `// Generated by`; edit
   the source under `contracts/` or `services/brain/knowledge`, then regenerate.
5. **Only `models` and `net` speak HTTP.** `contracts` defines `ModelPort`;
   `models` implements it, and changes when a provider's API does. `net` reaches
   the phone over the PC bridge and the gateway over its socket. A device reached
   over the bridge (`AdbDevice`) is a port in `net`, next to the client that
   reaches it, because the Windows sidecar uses it too.
6. **A local model is not `models`.** An on-device runtime is a separate adapter
   behind the same `ModelPort`; it never travels through `models`.
7. **One name, one module.** `com.hopa.contracts`, `com.hopa.engine`,
   `com.hopa.knowledge`, `com.hopa.providers`, `com.hopa.transport` and `com.hopa.turn`
   belong to these six modules. `com.hopa.capabilities`, `com.hopa.data` and
   `com.hopa.stores` belong to the Android app: only the app implements those
   stores, and the chat vocabulary they share lives in `contracts/chat`.
8. **No client imports another client.** Both import `packages/`.
9. **Generated files are committed**, and `--check` fails when they drift.
10. **One class per file, contracts may share.** A file of interfaces, enums,
    sealed or data classes carries no behaviour, so those can live together
    (`contracts/Observation.kt` holds the observation, its tree and the screen
    size). A plain class, an object or top-level functions keep their own file,
    named after it.

## What a client supplies

```
TurnContext(goal, history, memory, skills, installedApps, appFunctions,
            platform, vision, phoneAccess)
        |
        v
   AgentLoop  ->  TurnResult(records, answer, options, narration, usage, error)
```

The client also provides the ports: a `DevicePort` (accessibility, hidden display
or bridge), an `ApprovalGateway` (the sheet), a `RunRecorder` (Room or memory), a
`Clock`, and a `ModelPort` — from `net` today, from a local runtime later.

## Build and test

The modules apply two convention plugins from `build-logic/`: `hopa.kotlin-jvm`
(a plain JVM module on JDK 17) and, where a module is held to it,
`hopa.ktlint`. The Android app, the Windows sidecar and the backend all
`includeBuild` that composite build, so the module files stay the same in all
three.

```
./gradlew :contracts:compileKotlin :engine:test :knowledge:compileKotlin :stores:test :transport:test
./gradlew :app:compileDebugKotlin
./gradlew -p ../windows/sidecar test
```

## Generated code

| output | source | command |
|---|---|---|
| `knowledge/.../AppCatalog.kt` | `services/brain/knowledge/apps/*/APP.md`, `.../sites/*` | `build-app-catalog.py --kotlin` |
| `knowledge/.../ApprovalPolicyData.kt` | `contracts/policy/approval.v1.json` | `build-policy-data.py --kotlin` |
| `knowledge/.../PromptRules.kt` | `contracts/prompts/rules.v1.json` | `build-prompt-rules.py --kotlin` |

Each script also writes the ArkTS copy under `apps/harmony`. Add `--check` to any
of them to verify the committed files instead of writing.
