# packages — the client engine

Four Kotlin modules that the Android app and the Windows sidecar both build. No
`main`, no UI, no Android SDK.

| module | holds | package | depends on |
|---|---|---|---|
| `core` | loop, gate, prompt, observation, records, router, parser, contracts, ports | `com.hopa.core.*` | `know` |
| `know` | generated catalog, approval policy data, prompt rules | `com.hopa.know.*` | nothing |
| `state` | conversation, settings, approval, memory and skill contracts, plus their models | `com.hopa.state.*` | `core` |
| `remote` | model clients (OpenAI-compatible, stub) and the PC bridge client | `com.hopa.remote.*` | `core` |

```
apps/android ─┐
              ├─> core ──> know
apps/windows ─┘     ↑
                    ├── state
                    └── remote ──> okhttp
```

## Rules

1. **`core` imports no Android, no HTTP.** `checkNoAndroidImports` in Gradle and
   `tools/checks/check-android-structure.py` fail the build on a violation.
2. **`know` is generated.** Every file starts with `// Generated by`; edit the
   source under `contracts/` or `services/brain/knowledge`, then regenerate.
3. **`state` holds contracts, not storage.** Room, DataStore and Keystore live in
   `apps/android/data`; the interfaces they implement live here.
4. **`remote` is the only module with a network client.** `core` defines
   `ModelPort`; `remote` implements it.
5. **One name, one module.** `com.hopa.core`, `com.hopa.know`, `com.hopa.state`
   and `com.hopa.remote` belong to these four modules. `com.hopa.capabilities`
   and `com.hopa.data` belong to the platform adapters in `apps/android`.
6. **No client imports another client.** Both import `packages/`.
7. **Generated files are committed**, and `--check` fails when they drift.

## What a client supplies

```
TurnContext(goal, history, memory, skills, installedApps, appFunctions,
            platform, vision, phoneAccess)
        |
        v
   AgentLoop  ->  TurnResult(records, answer, options, narration, usage, error)
```

The client also provides the ports: a `DevicePort` (accessibility, hidden display
or bridge), an `ApprovalGateway` (the sheet), a `RunRecorder` (Room or memory), a
`Clock`, and a `ModelPort` from `remote`.

## Build and test

```
./gradlew :core:test :know:compileKotlin :state:test :remote:test
./gradlew :app:compileDebugKotlin
./gradlew -p ../windows/sidecar test
```

## Generated code

| output | source | command |
|---|---|---|
| `know/.../catalog/AppCatalog.kt` | `services/brain/knowledge/apps/*/APP.md`, `.../sites/*` | `build-app-catalog.py --kotlin` |
| `know/.../policy/ApprovalPolicyData.kt` | `contracts/policy/approval.v1.json` | `build-policy-data.py --kotlin` |
| `know/.../prompt/PromptRules.kt` | `contracts/prompts/rules.v1.json` | `build-prompt-rules.py --kotlin` |

Each script also writes the ArkTS copy under `apps/harmony`. Add `--check` to any
of them to verify the committed files instead of writing.
