# catalog - what HOPA can open, and which app answers

Two halves that always change together: the data that says what apps and sites
exist, what needs approval and how HOPA should speak, and the router that walks
that data to pick a target for a goal. Keeping them apart made every change
touch two modules and two build files.

## Generated data

Most of the data files are written by a script and start with `// Generated by`.
Edit the source under `spec/`, then regenerate; do not hand-edit.

| File | Source | Script |
|---|---|---|
| `ApprovalPolicyData.kt` | `spec/policy/approval.v1.json` | `build-policy-data.py --kotlin packages/catalog/src/main/kotlin/com/hopa/catalog/ApprovalPolicyData.kt` |
| `Catalog.kt` (apps and sites) | `spec/catalog/catalog.v1.json`, `services/brain/knowledge/{apps,sites}` | `build-app-catalog.py --kotlin packages/catalog/src/main/kotlin/com/hopa/catalog/Catalog.kt` |
| `PromptRule.kt` | `spec/prompts/rules.v1.json` | `build-prompt-rules.py --kotlin packages/catalog/src/main/kotlin/com/hopa/catalog/PromptRule.kt` |

The same scripts also write the ArkTS copies under `apps/harmony`, and `--check`
compares them.

## Hand-written

- `AppRouter`, `CatalogRoutes`, `RouteMatch`, `RouterHint`, `RouteTarget` - the
  route from a goal to a package, and the hints the prompt shows.
- `Knowledge`, `KnowledgeBundle`, `KnowledgeCodec`, `KnowledgeSource`,
  `FileKnowledgeStore` - the bundle and the store that can replace it.

## Rules

- **Nothing here imports Android.** `checkNoAndroidImports` enforces it.
- **No ktlint.** Most files are generated; reformatting them would break the
  "generated bundle is current" check.
- **The approval table is bundled, never downloaded.** A fetched catalog may say
  which app to open; it must not be able to make the gate less careful.
