# packages/know — generated knowledge

Every file here is written by a build script and starts with `// Generated by`.
Do not edit them by hand; edit the source and regenerate.

| File | Source | Script |
|---|---|---|
| `com/hopa/know/catalog/AppCatalog.kt` | `services/brain/knowledge/apps/*/APP.md`, `.../sites/*/SITE.md` | `tools/scripts/build-app-catalog.py --kotlin packages/know/src/main/kotlin/com/hopa/know/catalog/AppCatalog.kt` |
| `com/hopa/know/policy/ApprovalPolicyData.kt` | `contracts/policy/approval.v1.json` | `tools/scripts/build-policy-data.py --kotlin packages/know/src/main/kotlin/com/hopa/know/policy/ApprovalPolicyData.kt` |
| `com/hopa/know/prompt/PromptRules.kt` | `contracts/prompts/rules.v1.json` | `tools/scripts/build-prompt-rules.py --kotlin packages/know/src/main/kotlin/com/hopa/know/prompt/PromptRules.kt` |

The same scripts also write the ArkTS copies under `apps/harmony`, and
`--check` fails when either side is stale.

Why a separate module: the engine (`packages/core`) should not carry 1,600 lines
of generated data, and knowledge should be replaceable without touching the
loop. Nothing here may depend on another module.
